Rust প্রোগ্রামিং ভাষা

struct ব্যবহার করা একটি উদাহরণ প্রোগ্রাম

কখন আমরা struct ব্যবহার করতে চাইতে পারি, তা বুঝতে চলুন একটি প্রোগ্রাম লিখি, যা একটি আয়তক্ষেত্রের ক্ষেত্রফল হিসাব করে। আমরা শুরু করব আলাদা আলাদা variable দিয়ে, তারপর প্রোগ্রামটি refactor (আচরণ না বদলে কোড পুনর্গঠন) করতে করতে struct ব্যবহারে পৌঁছাব।

চলুন Cargo দিয়ে rectangles নামে একটি নতুন binary প্রজেক্ট বানাই, যা পিক্সেলে দেওয়া একটি আয়তক্ষেত্রের প্রস্থ আর উচ্চতা নিয়ে আয়তক্ষেত্রটির ক্ষেত্রফল হিসাব করবে। Listing 5-8-এ একটি ছোট প্রোগ্রাম দেখানো হয়েছে, যা আমাদের প্রজেক্টের src/main.rs-এ ঠিক এই কাজটি করার একটি উপায়।

এবার cargo run দিয়ে প্রোগ্রামটি চালান:

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.42s
     Running `target/debug/rectangles`
The area of the rectangle is 1500 square pixels.

প্রতিটি মাপ দিয়ে area function call করে এই কোড আয়তক্ষেত্রের ক্ষেত্রফল সফলভাবে বের করে ফেলে, তবে কোডটিকে আরও স্পষ্ট ও পাঠযোগ্য করতে আমরা আরও কিছু করতে পারি।

এই কোডের সমস্যা area-এর signature (function-এর নাম, parameter ও return type-এর ঘোষণা) দেখলেই স্পষ্ট:

fn main() {
    let width1 = 30;
    let height1 = 50;

    println!(
        "The area of the rectangle is {} square pixels.",
        area(width1, height1)
    );
}

fn area(width: u32, height: u32) -> u32 {
    width * height
}

area function-এর কাজ একটি আয়তক্ষেত্রের ক্ষেত্রফল হিসাব করা, কিন্তু আমাদের লেখা function-টির দুটি parameter আছে, আর প্রোগ্রামের কোথাও স্পষ্ট নয় যে parameter দুটি পরস্পর সম্পর্কিত। প্রস্থ আর উচ্চতা একসঙ্গে রাখলে কোডটি আরও পাঠযোগ্য আর সামলানো সহজ হতো। এটি করার একটি উপায় আমরা ইতিমধ্যে অধ্যায় 3-এর “tuple type” অংশে আলোচনা করেছি: tuple ব্যবহার করে।

tuple দিয়ে refactor করা

Listing 5-9-এ আমাদের প্রোগ্রামের আরেকটি সংস্করণ দেখানো হয়েছে, যা tuple ব্যবহার করে।

এক দিক থেকে এই প্রোগ্রামটি ভালো। tuple দিয়ে আমরা কিছুটা কাঠামো যোগ করতে পারি, আর এখন মাত্র একটি argument পাঠাচ্ছি। কিন্তু আরেক দিক থেকে এই সংস্করণটি কম স্পষ্ট: tuple তার উপাদানগুলোর নাম দেয় না, তাই আমাদের tuple-এর অংশগুলোতে index দিয়ে পৌঁছাতে হয়, ফলে আমাদের হিসাবটি কম সুস্পষ্ট হয়।

ক্ষেত্রফলের হিসাবে প্রস্থ আর উচ্চতা গুলিয়ে ফেললে কিছু যায় আসে না, কিন্তু আয়তক্ষেত্রটি স্ক্রিনে আঁকতে চাইলে তা গুরুত্বপূর্ণ হতো! আমাদের মনে রাখতে হতো যে width হলো tuple-এর index 0 আর height হলো tuple-এর index 1। অন্য কেউ আমাদের কোড ব্যবহার করলে তার পক্ষে এটি বুঝে বের করা আর মনে রাখা আরও কঠিন হতো। আমাদের কোডে ডেটার অর্থ প্রকাশ করিনি বলে এখন ভুল ঢুকে পড়া আরও সহজ।

struct দিয়ে refactor করা

ডেটায় লেবেল দিয়ে অর্থ যোগ করতে আমরা struct ব্যবহার করি। যে tuple ব্যবহার করছি, সেটিকে আমরা একটি struct-এ রূপান্তর করতে পারি, যাতে পুরোটার একটি নাম আর অংশগুলোরও নাম থাকে, Listing 5-10-এ যেমন দেখানো হয়েছে।

এখানে আমরা একটি struct সংজ্ঞায়িত করে তার নাম দিয়েছি Rectangle। কার্লি ব্র্যাকেটের ভেতরে field হিসেবে সংজ্ঞায়িত করেছি width আর height, দুটোরই type u32। তারপর main-এ Rectangle-এর একটি নির্দিষ্ট instance তৈরি করেছি, যার প্রস্থ 30 আর উচ্চতা 50।

আমাদের area function এখন একটি parameter দিয়ে সংজ্ঞায়িত, যার নাম আমরা দিয়েছি rectangle, আর যার type হলো একটি Rectangle struct instance-এর একটি immutable borrow। অধ্যায় 4-এ যেমন বলা হয়েছে, আমরা struct-টির ownership নেওয়ার বদলে সেটিকে borrow করতে চাই। এভাবে main তার ownership ধরে রাখে এবং rect1 ব্যবহার চালিয়ে যেতে পারে, আর এ কারণেই আমরা function signature-এ এবং যেখানে function call করি, সেখানে & ব্যবহার করি।

area function Rectangle instance-এর width আর height field পড়ে (লক্ষ করুন, borrow করা একটি struct instance-এর field পড়লে field-এর মানগুলো move হয় না, আর এ কারণেই প্রায়ই struct-এর borrow দেখতে পাবেন)। area-এর function signature এখন ঠিক আমরা যা বোঝাতে চাই তা-ই বলে: Rectangle-এর width আর height field ব্যবহার করে এর ক্ষেত্রফল হিসাব করো। এটি বোঝায় যে প্রস্থ আর উচ্চতা পরস্পর সম্পর্কিত, আর tuple-এর index মান 0 আর 1 ব্যবহারের বদলে মানগুলোকে বর্ণনামূলক নাম দেয়। স্পষ্টতার দিক থেকে এটি একটি জয়।

derive করা trait দিয়ে সুবিধা যোগ করা

প্রোগ্রাম ডিবাগ করার সময় Rectangle-এর একটি instance প্রিন্ট করে তার সব field-এর মান দেখতে পারলে কাজে লাগত। Listing 5-11-এ আগের অধ্যায়গুলোর মতো করে println! macro ব্যবহারের চেষ্টা করা হয়েছে। তবে এটি কাজ করবে না।

এই কোড compile করলে আমরা এই মূল বার্তাসহ একটি error পাই:

error[E0277]: `Rectangle` doesn't implement `std::fmt::Display`

println! macro (কোড তৈরি করে এমন কোড) অনেক ধরনের ফরম্যাটিং করতে পারে, আর ডিফল্টভাবে কার্লি ব্র্যাকেট println!-কে Display নামের ফরম্যাটিং ব্যবহার করতে বলে: যে আউটপুট সরাসরি শেষ ব্যবহারকারীর জন্য। এ পর্যন্ত দেখা primitive type (ভাষায় সরাসরি থাকা মৌলিক type)-গুলো ডিফল্টভাবে Display implement করে, কারণ একজন ব্যবহারকারীকে একটি 1 বা অন্য কোনো primitive type দেখানোর উপায় একটাই। কিন্তু struct-এর ক্ষেত্রে println!-এর আউটপুট কীভাবে ফরম্যাট করা উচিত, তা কম স্পষ্ট, কারণ দেখানোর সম্ভাবনা অনেক: কমা দেবেন কি দেবেন না? কার্লি ব্র্যাকেট প্রিন্ট করবেন? সব field দেখানো উচিত? এই অস্পষ্টতার কারণে Rust আমরা কী চাই তা অনুমান করার চেষ্টা করে না, আর println! ও {} placeholder-এর সঙ্গে ব্যবহারের জন্য struct-এর কোনো তৈরি Display implementation নেই।

error-গুলো পড়া চালিয়ে গেলে আমরা এই কাজের নোটটি পাব:

   |                        |`Rectangle` cannot be formatted with the default formatter
   |                        required by this formatting parameter

চলুন চেষ্টা করি! println! macro call এখন দেখতে হবে println!("rect1 is {rect1:?}");-এর মতো। কার্লি ব্র্যাকেটের ভেতরে :? নির্দেশক বসালে println! বোঝে যে আমরা Debug নামের একটি আউটপুট ফরম্যাট ব্যবহার করতে চাই। Debug trait আমাদের struct-টিকে এমনভাবে প্রিন্ট করতে দেয়, যা ডেভেলপারদের কাজে লাগে, যাতে কোড ডিবাগ করার সময় এর মান দেখতে পাই।

এই পরিবর্তনসহ কোডটি compile করুন। ধুর! এখনো error পাচ্ছি:

error[E0277]: `Rectangle` doesn't implement `Debug`

তবে আবারও compiler আমাদের একটি কাজের নোট দেয়:

   |                        required by this formatting parameter
   |

ডিবাগিং-এর তথ্য প্রিন্ট করার সুবিধা Rust-এ আছে, কিন্তু আমাদের struct-এর জন্য সেই সুবিধা চালু করতে আমাদের স্পষ্টভাবে বেছে নিতে হয়। এটি করতে struct-এর সংজ্ঞার ঠিক আগে outer attribute (যে item-এর ঠিক আগে বসে, তার ওপর প্রযোজ্য attribute) #[derive(Debug)] যোগ করি, Listing 5-12-এ যেমন দেখানো হয়েছে।

এবার প্রোগ্রামটি চালালে আমরা কোনো error পাব না, আর নিচের আউটপুট দেখব:

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.48s
     Running `target/debug/rectangles`
rect1 is Rectangle { width: 30, height: 50 }

চমৎকার! আউটপুটটি সবচেয়ে সুন্দর নয়, তবে এটি এই instance-এর সব field-এর মান দেখায়, যা ডিবাগিং-এর সময় নিশ্চয়ই কাজে লাগবে। বড় struct থাকলে আউটপুট একটু বেশি সহজপাঠ্য হওয়া কাজের; সেসব ক্ষেত্রে println! string-এ {:?}-এর বদলে {:#?} ব্যবহার করতে পারি। এই উদাহরণে {:#?} ধরন ব্যবহার করলে নিচের আউটপুট আসবে:

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.48s
     Running `target/debug/rectangles`
rect1 is Rectangle {
    width: 30,
    height: 50,
}

Debug ফরম্যাট ব্যবহার করে কোনো মান প্রিন্ট করার আরেকটি উপায় হলো dbg! macro ব্যবহার করা, যা একটি expression-এর ownership নেয় (println!-এর বিপরীতে, যা একটি reference নেয়), আপনার কোডে ওই dbg! macro call যে ফাইল ও লাইন নম্বরে আছে, তা ওই expression-এর ফলাফলের মানসহ প্রিন্ট করে, এবং মানটির ownership ফেরত দেয়।

Note: dbg! macro call করলে তা standard error কনসোল ধারায় (stderr) প্রিন্ট করে, println!-এর বিপরীতে, যা standard output কনসোল ধারায় (stdout) প্রিন্ট করে। stderr আর stdout নিয়ে আমরা অধ্যায় 12-এর “Redirecting Errors to Standard Error” অংশে আরও কথা বলব।

এখানে একটি উদাহরণ, যেখানে আমরা width field-এ assign হওয়া মান আর rect1-এর পুরো struct-এর মান—দুটোই জানতে আগ্রহী:

#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let scale = 2;
    let rect1 = Rectangle {
        width: dbg!(30 * scale),
        height: 50,
    };

    dbg!(&rect1);
}

30 * scale expression-এর চারপাশে আমরা dbg! বসাতে পারি, আর dbg! যেহেতু expression-এর মানের ownership ফেরত দেয়, তাই width field এমন মানই পাবে, যেন সেখানে dbg! call ছিলই না। আমরা চাই না dbg! rect1-এর ownership নিয়ে নিক, তাই পরের call-এ rect1-এর একটি reference ব্যবহার করি। এই উদাহরণের আউটপুট দেখতে এরকম:

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.61s
     Running `target/debug/rectangles`
[src/main.rs:10:16] 30 * scale = 60
[src/main.rs:14:5] &rect1 = Rectangle {
    width: 60,
    height: 50,
}

দেখতে পাচ্ছি, আউটপুটের প্রথম অংশটি এসেছে src/main.rs-এর লাইন 10 থেকে, যেখানে আমরা 30 * scale expression ডিবাগ করছি, আর এর ফলাফলের মান 60 (integer-এর জন্য implement করা Debug ফরম্যাটিং শুধু তাদের মান প্রিন্ট করে)। src/main.rs-এর লাইন 14-এর dbg! call &rect1-এর মান আউটপুট দেয়, যা হলো Rectangle struct। এই আউটপুট Rectangle type-এর সুন্দর করে সাজানো Debug ফরম্যাটিং ব্যবহার করে। আপনার কোড কী করছে তা বোঝার চেষ্টা করার সময় dbg! macro সত্যিই খুব কাজে আসতে পারে!

Debug trait ছাড়াও Rust আমাদের derive attribute-এর সঙ্গে ব্যবহারের জন্য বেশ কয়েকটি trait দিয়েছে, যেগুলো আমাদের নিজস্ব type-এ কাজের আচরণ যোগ করতে পারে। সেই trait আর তাদের আচরণগুলোর তালিকা আছে পরিশিষ্ট C-তে। নিজস্ব আচরণসহ এই trait-গুলো কীভাবে implement করতে হয় এবং কীভাবে নিজের trait তৈরি করতে হয়, তা আমরা অধ্যায় 10-এ দেখব। derive ছাড়াও আরও অনেক attribute আছে; আরও জানতে দেখুন Rust Reference-এর “Attributes” অংশ।

আমাদের area function খুবই নির্দিষ্ট: এটি শুধু আয়তক্ষেত্রের ক্ষেত্রফল হিসাব করে। এই আচরণকে আমাদের Rectangle struct-এর সঙ্গে আরও ঘনিষ্ঠভাবে বেঁধে দিলে কাজে লাগত, কারণ এটি অন্য কোনো type-এর সঙ্গে কাজ করবে না। চলুন দেখি কীভাবে area function-কে আমাদের Rectangle type-এর ওপর সংজ্ঞায়িত একটি area method-এ পরিণত করে এই কোড refactor করা চালিয়ে যাওয়া যায়।
